JSONsetRight User Guide

JSONsetRight is a Windows app for creating and editing JSON files, such as the settings files used by programs and websites, without having to type JSON yourself. You change values with ordinary controls: text boxes, number boxes, checkboxes and lists. JSONsetRight writes the JSON for you, so you can't introduce mistakes like a missing comma, an unclosed quote or a mismatched bracket.

This guide is for people who use JSONsetRight. You don't need to know how to program, and you don't need to know JSON in detail. Where a JSON term matters, the guide explains it.

Version: this guide describes JSONsetRight 3.2. (JSONsetRight was called SafeJSON before version 3.2.)

Installing JSONsetRight

What you need

  • Windows 10 or Windows 11.
  • Microsoft Edge WebView2. This is part of Windows 11 and current Windows 10, so you almost certainly have it already.
  • About 6 MB of disk space.

Download

  1. Open the JSONsetRight releases page on GitHub (your administrator can give you the link).
  2. Under the newest release (marked Latest), click JSONsetRight.exe to download it.

JSONsetRight is portable: there is no installer. The .exe file is the app.

  1. Move JSONsetRight.exe somewhere convenient, for example a Programs or Tools folder in your Documents. Avoid leaving it in Downloads, where it's easy to delete by accident.
  2. To make it easy to start, right-click JSONsetRight.exe and choose Pin to Start or Send to → Desktop (create shortcut).

Starting JSONsetRight for the first time

Double-click JSONsetRight.exe.

JSONsetRight is digitally signed by its publisher, Eric McFall, using a Microsoft-verified identity. You can check this yourself: right-click JSONsetRight.exe → Properties → Digital Signatures.

Windows may still show a warning for a new release:

You see What to do
"Windows protected your PC" Windows hasn't seen this release often yet. Click More info, check that the publisher is Eric McFall, then click Run anyway. This stops appearing as the release becomes known.
"Smart App Control blocked an app" or "An Application Control policy has blocked this file" You have an old, unsigned version: SafeJSON 1.0 or 2.0 (JSONsetRight's former name). Download the latest JSONsetRight.

Opening files with JSONsetRight from File Explorer

You can open a JSON file straight into JSONsetRight:

  1. In File Explorer, right-click a .json file.
  2. Choose Open with → Choose another app.
  3. Click More apps → Look for another app on this PC, find JSONsetRight.exe and select it.
  4. Tick Always use this app to open .json files if you want double-clicking to use JSONsetRight.

You can also drag files from File Explorer onto the JSONsetRight window.

Updating

Download the new JSONsetRight.exe and replace the old one. Your settings, recent files and backups are kept, because they're stored separately (see below).

Coming from SafeJSON?

JSONsetRight used to be called SafeJSON. Version 3.2 is the first under the new name, with the same features. If you used SafeJSON before:

  1. Save your work in SafeJSON first. JSONsetRight doesn't pick up unsaved changes or crash-recovery copies from SafeJSON.
  2. Settings start fresh. JSONsetRight keeps its data in a new folder, %LOCALAPPDATA%\JSONsetRight, so your theme, schema rules, backup count, recent files and per-file schema choices need setting up again in Settings.
  3. Old backups stay where they were, in %LOCALAPPDATA%\SafeJSON\backups. Backups… in JSONsetRight doesn't list them, but you can still open them: each folder there holds earlier versions of one file (source.txt says which), and you can open a .bak file with Compare… → Another file… after choosing All files in the file picker.
  4. Set up "Open with" again for JSONsetRight.exe (see Opening files with JSONsetRight from File Explorer).
  5. Delete the old program and folder when you're ready: remove SafeJSON.exe, and once you no longer need its backups, the %LOCALAPPDATA%\SafeJSON folder.

The Help button in old SafeJSON versions no longer works; the guide is now at https://ericmcfall.github.io/JSONsetRight/.

Where JSONsetRight keeps its own data

JSONsetRight never changes your files except when you save. Its own data lives in %LOCALAPPDATA%\JSONsetRight (paste that into File Explorer's address bar to open it):

Folder or file What's in it
settings.json Your settings, recent files and schema choices
backups\ Earlier versions of files you've saved (see Backups)
recovery\ Unsaved work, kept in case JSONsetRight closes unexpectedly
schema-cache\ Downloaded schemas, so they work offline

Removing JSONsetRight

  1. Delete JSONsetRight.exe (and any shortcuts you made).
  2. Optionally, delete the %LOCALAPPDATA%\JSONsetRight folder to remove settings and backups.

Your JSON files are not affected.

Quick start

This walk-through takes about five minutes. You'll open a file, change some values, add a new setting, save, and undo a mistake.

1. Open a file

  1. Start JSONsetRight. The welcome screen appears.
  2. Click Open a file… (or press Ctrl+O) and choose a .json file.

The file opens in a tab. On the left is the tree, which shows everything in the file. On the right is the details panel, which shows the item you've selected.

Tip: to practise without risk, copy a file first and open the copy. You can always undo, but practising on a copy is reassuring.

2. Look around the tree

Each line in the tree is one setting. For example:

▾ { }  appsettings.json  {4}
    Aa  AllowedHosts: "*"
  ▾ { }  Logging: {1}
    ▸ { }  LogLevel: {2}
  • The badge at the start of each line shows what kind of value it is: Aa text, # number, ✓ true/false, { } a group of settings (an object), [ ] a list (an array), ∅ empty.
  • Click ▸ to open a group, and ▾ to close it.
  • The part before the colon is the setting's name (its key), and the part after it is its value.

3. Change a value

  1. Click a setting with a # (number) badge.
  2. In the details panel on the right, change the number in the Value box.
  3. Press Enter.

The change appears in the tree, and a ● dot on the tab shows you have unsaved changes.

Now try typing something that isn't a number, such as 12px. The box turns red and explains what it expects. JSONsetRight won't save an invalid value, so you can't break the file.

For a text value (Aa), type anything you like, including quotes " and backslashes \. JSONsetRight handles the special characters for you.

For true/false (✓), just tick or untick the checkbox.

4. Add a new setting

  1. Click the group ({ }) you want to add to. To add at the top level, click the first line of the tree.
  2. In the details panel under Add property, type a name for the new setting.
  3. Choose its type (for example Text or Number) and click Add.
  4. The new setting is selected, so type its value straight away.

If you type a name that already exists in that group, JSONsetRight tells you and won't add it. Duplicate names are a common cause of hard-to-find mistakes.

5. Save

Click Save (or press Ctrl+S). The ● dot disappears.

JSONsetRight keeps a copy of the previous version as a backup each time you save, so you can go back later with Backups….

6. Undo a mistake

Delete something: select it and press Delete. Then click Undo (or press Ctrl+Z). It's back. Undo remembers every change since you opened the file, and Redo (Ctrl+Y) re-applies what you undid.

What next?

  • A tour of the window explains every part of the screen.
  • Editing in the tree covers renaming, moving, duplicating and more.
  • If your file has a schema (a description of what it may contain), JSONsetRight can check the file and suggest settings: see Schemas.

Tabs

Each open file has a tab. A ● after the name means the file has unsaved changes.

  • Click a tab to switch to it, or press Ctrl+Tab to go to the next tab.
  • Click ×, middle-click the tab, or press Ctrl+W to close it. If it has unsaved changes, JSONsetRight asks whether to Save, Don't save, or Cancel.
  • Opening a file that's already open just switches to its tab.

Message bar

Information and warnings appear in a bar below the tabs, for example when a file was changed by another program. Click Dismiss to hide the message.

Tree

The tree shows the whole file as an outline. Each line shows:

Part Meaning

// comment A comment written in the file next to this setting (hover to read it all)
⛔ / ⚠ A problem with this setting (hover to read it; shown as (!) in the diagram above). A small ● on a closed group means something inside it has a problem

Value types (badges)

Badge Type Example Notes

Details panel

The right-hand panel shows the selected setting:

  • Path: where the setting is in the file, such as Logging.LogLevel.Default. Click Copy path to copy it.
  • Schema help: if the file has a schema, a description of the setting appears here.
  • Key: the setting's name, which you can rename here. For list items, Position shows the item's number.
  • Type: change the kind of value. If the schema expects certain types, they're marked (expected).
  • Value: an editor suited to the type: a text box, a number box, a checkbox, or a dropdown when only certain values are allowed.
  • Add property / Add item: shown for groups and lists.
  • Comments: any comments the file has for this setting.
  • Move up, Move down, Duplicate, Delete.

Problems panel

Appears at the bottom when the file has problems. Each line shows where the problem is, what's wrong, and where the check came from:

  • JSONsetRight: built-in checks, such as duplicate names or numbers too large to store exactly.
  • Schema: the file breaks a rule in its schema.

Click a problem to jump to it.

Status bar

The blue bar at the bottom shows, from left to right:

Welcome screen

When no files are open, JSONsetRight shows Open a file…, New file, and your Recent files. Click a recent file to reopen it.

Editing in the tree

Everything you change goes through JSONsetRight's checks, so the file always stays valid. Every change can be undone with Undo (Ctrl+Z).

Selecting and moving around

  • Click a line to select it. Its details appear on the right.
  • ▸ / ▾ (or → / ← on the keyboard) open and close groups and lists.
  • ↑ / ↓ move the selection up and down.
  • ← on a closed item jumps to the group it belongs to.

Changing a value

Select the setting, then use the Value editor in the details panel. Each type has its own editor:

Type Editor How to finish
Text A text box. It grows for longer text and accepts line breaks Click elsewhere, or press Ctrl+Enter
Number A number box. Invalid input turns red and is never saved Press Enter or click elsewhere
True / false A checkbox Changes immediately
Null Nothing to edit: change the type to give it a value
Object / list Shows how many entries it has; select an entry to edit it

Press Escape in a text or number box to cancel your typing.

Under the text box, JSONsetRight shows how the text will be saved, for example "He said \"hi\"". Quotes, backslashes and line breaks are converted automatically. You never need to type escape codes yourself.

Numbers can be written as 42, -7, 3.14, or 1e6 (one million). JSONsetRight rejects things like 12px, 1,000, .5, or NaN, because standard JSON doesn't allow them. (JSON5 files are more relaxed: there, .5, +1, hex numbers like 0xFF, Infinity and NaN are accepted. See File types.) If a whole number is too large for most programs to store exactly (more than about 9 million billion), JSONsetRight saves it exactly as you typed it and shows a warning.

Editing directly in the tree

Double-click a value in the tree to edit it in place, then press Enter to save or Escape to cancel. Double-clicking a true/false value flips it. Text that contains line breaks opens in the details panel instead, so no line breaks are lost.

Renaming a setting

  • Select it and change the Key box in the details panel, then press Enter, or
  • Double-click the name in the tree, or press F2.

JSONsetRight won't accept an empty name, or a name already used by another setting in the same group. List items don't have names; they're numbered by position.

Adding settings and list items

Select the group ({ }) or list ([ ]) you want to add to. In the details panel:

  • For a group (Add property): type a name, choose a type, and click Add (or press Enter).
  • For a list (Add item): choose a type and click Add. The item is added at the end.

The new entry starts with a sensible empty value ("", 0, false, null, {} or []) and is selected, ready for you to type its value.

If the file has a schema, the name box suggests the settings the schema knows about, new entries start with the schema's default value, and missing required settings are listed with one-click + buttons.

Deleting

Select the setting or item and press Delete, click Delete in the details panel, or right-click it and choose Delete. The selection moves to the next item.

Duplicating

Press Ctrl+D, or use Duplicate. The copy appears right after the original. Duplicated settings in a group are named name copy, name copy 2, and so on; rename them as needed.

Moving (changing the order)

  • Drag a line up or down within the same group or list. A blue line shows where it will land.
  • Or press Alt+↑ / Alt+↓, or use Move up / Move down.

You can only reorder within the same group or list. To move a setting into a different group, duplicate it there (copy its value) and delete the original.

The order of settings in a group usually doesn't matter to programs, but it can make files easier to read. The order of items in a list often does matter.

Changing a value's type

Use the Type dropdown in the details panel, or right-click → Change type to.

JSONsetRight converts the value where it can: 5 becomes "5" as text, and "42" becomes 42 as a number. If something would be lost, it asks first. For example, changing a group that contains 3 settings into text would delete those settings. You can undo any type change.

Right-click menu

Right-click any line (or press Shift+F10):

Item What it does
Rename key (F2) Rename the setting
Duplicate (Ctrl+D) Copy it, placing the copy right after it
Move up / Move down (Alt+↑ / Alt+↓) Reorder it
Delete (Del) Remove it
Change type to Convert it to another type
Copy path Copy its location, e.g. servers[0].host
Copy value as JSON Copy its value as JSON text, to paste elsewhere

Searching

Type in the Search box (Ctrl+F). The tree shows only matching settings, plus the groups that contain them, with matches highlighted. The search covers both names and values and ignores capital letters. Clear the box to see everything again. Drag-to-reorder is turned off while searching.

Comments

Files that allow comments (see File types) may contain notes like // The port to listen on. JSONsetRight shows a setting's comment in green next to it in the tree, and in full in the details panel. Comments are always kept exactly as they are when you edit and save. JSONsetRight doesn't add, edit or delete comments in the tree; use Text mode for that.

Undo and redo

  • Undo (Ctrl+Z) steps back one change at a time, as far back as when you opened the file.
  • Redo (Ctrl+Y or Ctrl+Shift+Z) re-applies what you undid.
  • Making a new change after undoing clears the redo history.

While you're typing in a box, Ctrl+Z and Ctrl+Y undo and redo your typing in that box instead.

Table view

Many files contain lists of similar items, such as users, products or servers, where each item has the same kinds of settings. Table view shows such a list as a grid, like a spreadsheet: one row per item, one column per setting.

 #   sku     name     qty    price   active
 1   A-100   Bolt     250    0.12    ☑
 2   B-200   Nut      1200   0.05    ░░░░░    ← hatched: this item has no "active" setting
 3   C-300   Washer   0      0.02    ☐

Opening a table

  1. In the tree, select a list whose items are groups ([ ] containing { } items), or anything inside such a list.
  2. Click Table in the toolbar, or ▦ Show this list as a table in the details panel.

If Table is greyed out, the selection isn't inside a list of groups. Table view needs a list where every item is a group of settings.

Click ‹ Tree (top left) to go back to the tree.

Reading the table

  • Columns are every setting name that appears in any row, in the order first seen. The small badge shows the column's usual type. Hover over a column name to see how many rows have it, plus the schema's description of it, if there is one.
  • Hatched (striped) cells mean that row doesn't have that setting at all, which is different from having an empty value.
  • True/false cells show a checkbox you can click directly.
  • Groups and lists inside a cell show as {2} › or [3] ›. Click to open them in the tree.
  • ⛔ next to a row number, or a red line under a cell, marks a problem. Hover to read it.

Editing cells

  • Click a cell to select it. Use the arrow keys or Tab to move between cells.
  • Double-click, or press Enter or F2, to edit the selected cell. Press Enter to save or Escape to cancel.
  • Numbers are checked as you type, just like in the details panel.
  • If the schema lists allowed values for a column, editing shows a dropdown.
  • Space toggles a true/false cell.
  • Delete removes that setting from the row; the cell becomes hatched.

Filling in a hatched cell adds the setting to that row, placed in column order, with the column's usual type.

Rows

Hover over a row number to see its buttons:

Button What it does
↑ / ↓ Move the row up or down
⧉ Duplicate the row
× Delete the row

+ Add row (top right) adds a new row at the end, with every column filled in with an empty value or the schema's default.

Columns

  • + Add column adds an empty column. It becomes part of the file as soon as you fill in a cell.
  • Rename a column: double-click its name. Every row that has the setting is renamed. If any row already has a setting with the new name, nothing is renamed and JSONsetRight explains why.
  • Remove a column: hover over its name and click ×. JSONsetRight asks before removing the setting from every row.

Sorting

Click a column name to sort the rows by it. Click again to reverse the order (▲ / ▼), and a third time to stop sorting. Numbers sort by value, text sorts naturally (item2 before item10), and rows without the setting go last.

Sorting only changes what you see. A banner reminds you that the file's order hasn't changed. Click Save this order to the file to make the order permanent (one undo step), or Unsort to go back to the file's order. Row moves are turned off while sorted.

Undo

Every change in the table, including renaming or removing a column across all rows, is a single undo step. Press Ctrl+Z to undo it.

Text mode

Text mode shows the file as text in a code editor, the same editor used in Visual Studio Code. It's for people who prefer typing JSON, for quick large edits like pasting a block, and for fixing files that aren't valid JSON.

Click Text in the toolbar, or press Ctrl+Shift+T, to switch. Click Tree (or press Ctrl+Shift+T again) to switch back.

How it stays safe

What you type is applied to the file only once it's valid:

  • When you pause typing, JSONsetRight checks the text. If it's valid, the change is applied, and each pause becomes one undo step.
  • If it isn't valid, a red banner shows exactly where the problem is, for example "Line 5, column 3: Expected ','". Click Go to problem to jump there.
  • While there's a problem, you can't save or switch to the tree. Fix the text first. The rest of JSONsetRight keeps using the last valid version.

The editor underlines mistakes as you type, and if the file has a schema, it suggests setting names and values as you type (press Ctrl+Space to see suggestions).

Standard JSON files stay standard. If the file was plain JSON when you opened it, text mode won't accept comments or trailing commas, because the programs that read it might not understand them. See File types.

Opening files that aren't valid JSON

If you open a file that has a mistake in it, JSONsetRight opens it in text mode instead of refusing it. A message says what's wrong and where. Fix the mistake, and once the text is valid the tree and saving become available. The file's original line endings and encoding are kept.

Common mistakes and their messages:

Message Usual cause
Expected ',' A missing comma between two settings or list items
Expected a property name in double quotes A comma after the last setting (in standard JSON), or a name without quotes
Expected a value An extra comma, like [1, , 2], or nothing after a :
String is not closed A missing closing "
Expected '}' or Expected ']' A missing closing bracket
Unexpected content after the end of the JSON Extra text after the final }

Editor features

The code editor has its own tools:

Keys Action
Ctrl+F / Ctrl+H Find / find and replace
Ctrl+Space Show suggestions
Shift+Alt+F Format the text
Ctrl+Z / Ctrl+Y Undo / redo typing
Alt+↑ / Alt+↓ Move a line up or down
Ctrl+/ Comment or uncomment a line (in files that allow comments)

Undo on the toolbar undoes whole applied changes, and also throws away any text that wasn't valid yet.

Checking a selected setting

Clicking a problem in the Problems panel while in text mode moves the cursor to that setting in the text.

Schemas

A JSON Schema is a separate file that describes what another JSON file may contain: which settings exist, what type each one is, which values are allowed, which are required, and what they mean. Many programs publish schemas for their settings files, for example on schemastore.org.

When a file has a schema, JSONsetRight becomes much more helpful:

  • It checks the file. Problems are listed in plain language ("Must be one of: development, staging, production"), marked in the tree, and shown in the details panel.
  • It explains settings. The schema's description of the selected setting appears at the top of the details panel.
  • It offers choices. When only certain values are allowed, the value editor becomes a dropdown.
  • It suggests settings. The Add property name box lists the settings the schema knows about, with their descriptions. New settings start with the schema's default value.
  • It lists what's missing. Required settings that are missing appear as + name buttons.
  • It shows defaults. Under the value you'll see Default: … with a Use default link.
  • It warns on save. Saving a file that breaks its schema shows the problems and lets you choose Save anyway, Show first problem, or Cancel.

How JSONsetRight finds a file's schema

JSONsetRight looks in this order and uses the first one it finds:

  1. A schema you chose for this file (see below).
  2. The file's own "$schema" setting, a top-level setting that names its schema, for example:
    { "$schema": "https://json.schemastore.org/package.json", "name": "my-app" }
    It can be a web address, or a path relative to the file such as "./app.schema.json".
  3. A filename rule from Settings, for example "files named appsettings*.json use C:\schemas\appsettings.schema.json".

The status bar shows the result: Schema: name, No schema, Loading schema…, or ⚠ Schema not loaded (hover over it to see why).

Choosing a schema for a file

Click the schema item in the status bar. The schema dialog shows which schema is in use and why, and lets you:

Button What it does
Choose a schema file… Use a schema file from your PC for this file
web address + Use Use a schema from the web, e.g. https://json.schemastore.org/tsconfig.json
Don't use a schema Turn schema checking off for this file
Back to automatic Forget your choice; use $schema or a filename rule again
Reload schema Re-read the schema files and download web schemas again (use this after a schema changes)

Choices are remembered per file. The file has to be saved somewhere before you can choose a schema for it.

Schemas from the web

Web schemas are downloaded the first time they're needed and kept on your PC, so they keep working without an internet connection. Use Reload schema to fetch a newer copy.

When a schema problem is reported

Schema problems aren't syntax errors: the file is valid JSON, but it doesn't follow the rules the program expects. Programs reading the file may reject it or behave unexpectedly. Typical messages:

Message Meaning
Missing required property "name" The setting must exist; use the + name button to add it
"colour" is not a known property here The schema doesn't allow this setting; it may be misspelled
Should be a number The value has the wrong type
Must be one of: … Only the listed values are allowed
Must be <= 65535 The number is outside the allowed range
Should be a valid hostname / email / uri The text isn't in the expected format

Notes

  • JSONsetRight supports the common schema versions (draft-04, -06, -07, 2019-09 and 2020-12), including schemas that refer to other schema files.
  • Deprecated settings (ones the schema says are no longer used) are marked Deprecated in the details panel.

  • "What have I changed since I last saved?"
  • "How does the test server's config differ from the live one?"
  • "What did this file look like before last Tuesday's change?"

Reading the comparison

The current file is on the left and can be edited. The other version is on the right.

Only the data is compared. These differences are ignored:

  • comments
  • the order of settings within a group
  • quote style (in JSON5 files)

Lists are lined up by matching items, so inserting one item shows as a single addition instead of making everything after it look changed.

File types and formatting

The three kinds of JSON file

JSONsetRight works with three closely related formats. It detects the format automatically and shows it in the status bar.

Status bar Format Typical files What it allows
JSON Standard JSON package.json, appsettings.json, API data Only the strict rules: double-quoted names and text, no comments, no trailing commas
JSON with Comments JSONC VS Code settings.json, tsconfig.json Standard JSON plus // and /* */ comments and trailing commas
JSON5 JSON5 .json5 config files Also unquoted names, 'single quotes', hex numbers (0xFF), Infinity, NaN, .5, +1, and text continued over several lines

A trailing comma is a comma after the last item: [1, 2, 3,].

JSONsetRight never changes a file's format by itself. A standard JSON file stays standard JSON: JSONsetRight never adds comments to it, and text mode refuses comments and trailing commas in it, because programs that expect standard JSON would fail to read them.

JSON5 files keep their style

In JSON5 files, JSONsetRight writes new content the way the file already does: if the file uses unquoted names and single-quoted text, new settings follow suit. Renamed settings and edited text keep their original quoting. (Format is not available for JSON5 files yet.)

What JSONsetRight keeps exactly as it was

When you change something, JSONsetRight rewrites only that part of the file. Everything else stays byte-for-byte the same:

  • comments, wherever they are
  • indentation (spaces or tabs, and how many)
  • line endings (Windows CRLF or Unix LF)
  • the order of settings
  • blank lines and alignment
  • lists written on one line, like ["a", "b"], which stay on one line
  • numbers exactly as written (1.50 stays 1.50; very large numbers aren't rounded)
  • a byte-order mark (BOM) at the start of the file, if it had one

This keeps changes small and easy to review, which matters if your files are tracked in a system such as git.

New content is indented to match the file.

Formatting

Format (Shift+Alt+F) re-indents the whole file neatly, one setting per line, keeping comments. It's useful for files that were written on one long line. Format is one undo step.

By default, Format keeps the file's current indentation style. You can choose 2 spaces, 4 spaces or tabs instead in Settings.

Trailing commas

JSONC files may contain trailing commas. In Settings, choose:

  • Keep them (default), or
  • Remove them when saving: JSONsetRight removes them as an undoable step just before saving.

JSON5 files always keep their trailing commas, since they're a normal part of JSON5.

Encoding and size limits

  • Files must be UTF-8 text, the standard for JSON. Other encodings are refused with a message, rather than risking damage to the file.
  • Files up to 10 MB can be opened. JSONsetRight is designed for configuration files, which are usually far smaller.

Large numbers

Most programs can only store whole numbers up to about 9 million billion (9,007,199,254,740,991) exactly. JSONsetRight keeps larger numbers exactly as written, but shows a warning in the Problems panel, because the program reading the file may round them.

Duplicate names

If a file somehow contains the same setting name twice in one group, JSONsetRight reports it in the Problems panel. Most programs silently use only the last one, which is a common source of confusing bugs. JSONsetRight never lets you create duplicates yourself.

Saving and safety features

JSONsetRight is built so that you can't damage a file by accident, and so that you can get your work back if something goes wrong.

The file is always valid

Every change you make in the tree, the table or the details panel is checked before it's applied. A change that would produce invalid JSON is refused. In text mode, text is only applied once it's valid, and saving is blocked while it isn't.

Saving

  • Save (Ctrl+S) writes the file. A file that has never been saved asks for a name first.
  • Save as… (Ctrl+Shift+S) saves under a new name or location. The tab then refers to the new file.

Crash-safe saving: JSONsetRight writes to a temporary file next to yours and swaps it in only once it's complete. If the PC loses power mid-save, your original file is still intact.

Before saving, JSONsetRight may ask you about:

Question Why Your choices
"…doesn't match its schema" The file breaks rules in its schema Save anyway, Show first problem, Cancel
"…was changed by another program" Someone else saved the file since you opened it Save anyway (their version is kept as a backup), Cancel

Backups

Each time you save over a file, JSONsetRight first keeps a copy of the previous version. By default it keeps the 5 most recent per file; you can change this, or turn backups off, in Settings.

To restore one:

  1. Open the file and click Backups….
  2. Pick a version by its date and time, and click Restore.

The restored version replaces what's on screen but isn't saved yet: check it, then Save, or press Ctrl+Z to undo the restore. You can also compare the current file with a backup first.

Backups are stored in %LOCALAPPDATA%\JSONsetRight\backups, not next to your files, so they don't clutter your folders or project repositories.

Crash recovery

Every 30 seconds, JSONsetRight keeps a private copy of any unsaved changes. If JSONsetRight closes unexpectedly (a crash, a power cut, or Windows restarting for updates), the next time you start it you'll see "Recover unsaved work?":

  • Recover reopens your unsaved changes in tabs, ready to review and save.
  • Discard throws them away.
  • Cancel decides later (you'll be asked again next time).

Recovery copies are deleted when you save or close normally.

Changes made by other programs

JSONsetRight checks open files every few seconds, and whenever you switch back to its window:

  • If you have no unsaved changes, it reloads the file automatically and tells you. Press Ctrl+Z to go back to what you had.
  • If you do have unsaved changes, it asks: Load their version (undoable) or Keep mine.
  • If the file was deleted or moved, it tells you; saving creates it again.
  • If the other program left the file invalid (for example mid-save), JSONsetRight keeps your version and tells you.

Closing

  • Closing a tab with unsaved changes asks: Save, Don't save, or Cancel.
  • Closing the JSONsetRight window asks about each file with unsaved changes.

Undo

Every change, including deleting, moving, changing type, restoring a backup, reloading after another program's change, and formatting, can be undone with Ctrl+Z, step by step, back to when you opened the file.

Schema rules

Schema rules give files a schema automatically based on their name, for files that don't name their own schema.

  1. Click + Add rule.
  2. In the first box, type a file-name pattern. * matches anything and ? matches one character:
    • appsettings*.json matches appsettings.json and appsettings.Development.json
    • *.config.json matches any file ending in .config.json
    • Include a folder, as in C:\projects\*\settings.json, to match the whole path
  3. In the second box, enter the schema's file path or web address, or click … to choose a file.

Click × to remove a rule. A file's own "$schema", or a schema you chose for that file in the schema dialog, takes priority over these rules.

Where settings are stored

In %LOCALAPPDATA%\JSONsetRight\settings.json. To reset everything to the defaults, close JSONsetRight and delete that file.

Troubleshooting and FAQ

Starting JSONsetRight

"Windows protected your PC" appears. Click More info, check the publisher is Eric McFall, and click Run anyway. This warning appears for new releases until Windows has seen them often. It's likely right after the change from SafeJSON to JSONsetRight, because Windows sees a program file with a new name.

"Smart App Control blocked an app" / "An Application Control policy has blocked this file". You're running SafeJSON 1.0 or 2.0 (JSONsetRight's former name), which aren't signed. Download the latest JSONsetRight.

My settings, recent files or backups are gone after switching from SafeJSON. JSONsetRight keeps its data in a new folder and starts fresh. Your old backups are still in %LOCALAPPDATA%\SafeJSON\backups. See Coming from SafeJSON?.

Double-clicking a .json file still opens SafeJSON (or nothing). File associations point to the old program. Set up "Open with" again for JSONsetRight.exe; see Installing.

Nothing happens, or an error mentions WebView2. JSONsetRight needs Microsoft Edge WebView2, which comes with Windows 11 and current Windows 10. Run Windows Update, or install the "Evergreen WebView2 Runtime" from Microsoft's website.

Opening files

"…isn't valid JSON yet (line 3, column 5: …)". The file has a mistake. JSONsetRight opens it in text mode so you can fix it. See the table of common mistakes there.

"…is not UTF-8 text, so JSONsetRight can't open it safely." The file uses an older text encoding. Open it in Notepad, choose File → Save as, set Encoding to UTF-8, and save. Then open it in JSONsetRight.

"…is larger than JSONsetRight supports (10 MB)." JSONsetRight is designed for configuration files. Use a text editor for very large data files.

Table is greyed out. Select a list whose items are all groups of settings ({ }), or something inside one. See Table view.

Editing

My number turns red. It isn't a valid JSON number. Use digits with an optional -, one . for decimals, and e for powers of ten: 1500, -2.5, 1e6. Don't use thousands separators or units (1,500, 12px).

I can't add a setting: "This object already has a key named …". Each name can appear only once in a group. Choose another name or edit the existing setting.

I need to move a setting into another group. Copy its value (right-click → Copy value as JSON), add a setting with the same name in the other group, paste the value in text mode or re-enter it, then delete the original.

Format says it isn't available. Format isn't available for JSON5 files yet. Your edits still keep the file's layout.

I want to add or edit comments. Use text mode in a JSON with Comments or JSON5 file. Standard JSON files can't have comments.

Schemas

The status bar says "⚠ Schema not loaded". Hover over it to see why. Common causes: the schema file was moved, the web address is wrong, or there's no internet connection and the schema hasn't been downloaded before. Click the item to choose another schema or Reload schema.

The schema is wrong or out of date for my program's version. Click the schema item in the status bar and choose a different schema, or Don't use a schema. Schema problems never stop you saving.

Every setting is "not a known property here". The file is probably being checked against the wrong schema. Check which one in the schema dialog.

Saving

"Can't be saved until it's valid JSON." Text mode has a mistake; the red banner shows where. Fix it, then save.

"Windows denied access to …" The file is read-only, in a protected folder (such as Program Files), or open and locked in another program. Close the other program, or use Save as… to save elsewhere.

I saved something by mistake. Click Backups… and restore the previous version, then save again. Or press Ctrl+Z (undo still works after saving) and save again.

FAQ

Does JSONsetRight send my files anywhere? No. Files are read and saved only on your PC. The only internet access is downloading schemas from web addresses that a file (or you) names.

Will JSONsetRight change parts of my file I didn't touch? No. Only the part you change is rewritten; comments, spacing, order and line endings are kept. The exceptions are things you ask for: Format, and removing trailing commas if you turned that on.

Can several people edit the same file? JSONsetRight notices when another program or person saves the file while you have it open, and asks before overwriting their changes. It doesn't merge edits automatically, but Compare helps you combine them.

Can I use JSONsetRight on a Mac or Linux? Not currently. JSONsetRight is built for Windows.

Where are my backups and settings? In %LOCALAPPDATA%\JSONsetRight. See Installing.

Glossary

Array (list) An ordered list of values, written [1, 2, 3]. Items are numbered from 0. Badge: [ ].

Backup A copy of a file's previous version, kept automatically each time you save. See Backups.

Boolean (true / false) A value that is either true or false. Badge: ✓.

BOM (byte-order mark) An invisible marker some programs put at the start of a text file. JSONsetRight keeps it if it's there.

Comment A note in a file that programs ignore: // like this or /* like this */. Allowed in JSON with Comments and JSON5, not in standard JSON.

CRLF / LF The two styles of line ending. Windows traditionally uses CRLF; Linux and macOS use LF. JSONsetRight keeps whichever the file uses.

Default The value a schema says a setting has when it isn't specified.

Deprecated A setting the schema says is no longer used, or will be removed.

Enum (allowed values) A fixed list of values a schema allows for a setting. JSONsetRight shows these as a dropdown.

Escape characters Codes like \" or \n used inside JSON text to represent quotes and line breaks. JSONsetRight adds them automatically; you never type them.

JSON JavaScript Object Notation: a common text format for settings and data, made of objects, arrays, text, numbers, true/false and null.

JSONC (JSON with Comments) JSON that also allows comments and trailing commas. Used by VS Code and others.

JSON5 A friendlier extension of JSON that also allows unquoted names, single quotes, hex numbers and more.

Key (name) The name of a setting in an object, such as "port" in "port": 8080.

Null A deliberately empty value, written null. Badge: ∅.

Number A numeric value such as 8080, -1.5 or 1e6. Badge: #.

Object (group) A group of named settings, written { "name": value, … }. Badge: { }.

Path The location of a setting in a file, such as servers[0].host: the host setting of the first item in the servers list.

Property Another word for a named setting in an object (a key and its value).

Required A setting a schema says must be present.

Schema (JSON Schema) A file describing what another JSON file may contain. See Schemas.

String (text) A text value, written in quotes: "hello". Badge: Aa.

Trailing comma A comma after the last item in a list or object: [1, 2,]. Allowed in JSONC and JSON5 only.

UTF-8 The standard way of storing text in files, and the encoding JSON files use.

Value The data part of a setting: text, a number, true/false, null, an object or a list.
